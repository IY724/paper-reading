# 批注方法论

本文件管「写什么」。版式与脚本见 SKILL.md。

## 1. 切段

**全文照录，不摘取。** 交付物必须含以下五类内容，缺一即为摘要而非精读：

| 内容 | 处理方式 |
|---|---|
| 正文全部自然段 | 逐段成 row，跨页断开的段落要合并回一段，不得因「不重要」跳过 |
| 图表原始题注 | 中文图注按图实写，另用 `.fcap-en` 原样保留英文题注 |
| 刊头元信息 | 投稿/接收/发表日期、单位、通讯作者、关键词、资助、许可，放 `.meta-list` |
| 尾件 | Acknowledgments、Author Contributions、Conflicts of Interest、版权行，各成一段并批注 |
| 参考文献 | 全录、保留原文不翻译，用 `.refs-list`；发现的引用错误在该条加 `.refnote` |

判断是否漏内容，不要靠眼看：把 PDF 正文逐行与成品里 `.en`/`figcaption`/`.body`/`td` 的文本做行级包含比对，
列出未出现的行。句子级或探针级都会被行内公式打断而产生假阳性。

段号规则：以原刊自然段为单位，一段一个 `article.row`，全局连续编号 ¶ 01…¶ NN。
摘要、结论、图注独立成段。过长的段（>220 词）可按论证转折拆成两段，但要在
`.pnum` 里注明 `¶ 12a / ¶ 12b` 之外的做法是保持原段不拆——默认不拆。
公式独占行不单独成段，归入它所属的段。

## 2. 五维判定

每段选**一个**主维度（决定 `aside.note` 的 class 与 `.dim` 文字）。
段内高亮 `mark` 的颜色必须就是这个主维度，不允许一段里混几种颜色。判定顺序，命中即停：

| 顺序 | 维度 | class / mark | 命中条件 |
|---|---|---|---|
| 1 | 让步 / 反驳 | `c-concession` / `g` | 出现 however / although / nevertheless / limitation / does not capture，或作者主动交代简化、回应潜在质疑 |
| 2 | 实证证据 | `c-evidence` / `b` | 给出可核对的数值、表格、曲线、试验对照、误差百分比 |
| 3 | 方法论 | `c-method` / `p` | 描述模型构造、算法步骤、实现细节、网格与求解设置 |
| 4 | 关键概念 | `c-concept` / `r` | 定义术语、给出符号含义、引入新变量 |
| 5 | 核心论点 | `c-thesis` / `t` | 以上都不是，且该段在主张「应该怎样 / 本文做了什么」 |

高亮密度：**每段最多 1 处**，标该段删掉最可惜的那一句；过渡段、刊头元信息、
尾件、参考文献可以不标。整段高亮等于没有高亮，一段两三种颜色也等于没有颜色。
Khan 2018 从 95 处（17 段 2 处、13 段 3 处、2 段 4 处）精简到 46 处后，
五色各 7–13 处，每处的颜色才真正在说一件事。
选句次序：先取与该段主维度同色的候选；同色有多个时取被批注引用最多的那句；
一段内没有同色候选，就改写那句的 class 或换批注维度，不要留两种颜色并存。

## 3. 批注三栏

`段落功能`：一句话，动词开头。例「排除线性 Goodman 近似，选定归一化模型作为寿命内核」。
不要写「本段介绍了……」这种空转。

`逻辑角色`：说清它**承上启下**接的是哪几段。例「承接 ¶ 04 的试验成本问题，为 ¶ 14 的参数修正提供入口；
若删去此段，后文的统一载荷参数失去动机」。必须出现具体段号。

`技巧与漏洞`：先给一个值得学的写法，再给一个可核实的疑点。两者都要落到证据。
- 好的写法：「用端点自洽性（n=Nf 时 σr=σ）检验被复现模型，不依赖任何新数据，读者可纸面复核」。
- 坏的写法：「论证严密，逻辑清晰」——无信息量，禁止。
- 疑点必须可核实：指出表几第几行、式几的哪一项、哪两段互相矛盾。
  无法核实的怀疑写成「文中未说明 X」，不要写成「作者错了」。

没有疑点的段就只写技巧，不要硬凑。

`标注`：第四栏，色块 + 「被高亮的那句原文」逐字照抄（含 `<sub>/<sup>`）。
它回答读者看到颜色后的第一个问题——「这个颜色指的是哪一句」。
`check_html.py` 会比对高亮片段与该栏文字，不一致直接 FAIL；
没有高亮的段落不写这一栏。

## 4. 译文

意译为主，读起来像中文学术论文，不逐字直译。不加高亮。
术语用本领域通行译法并在全文保持一致（首次出现可括注英文）。
符号、下标、上标、公式编号原样保留，用 `<sub>` `<sup>`，不要改成纯文本。
引用编号 [16] 原样保留，即使它看起来是错的——错误在批注里指出，不在译文里悄悄改。

## 5. 公式与表格

**正文引用了就必须呈现。** 段落里出现「式 (N)」或「表 N」，该段 `.text` 内必须有对应的
`.eq` / `.tbl` 块；`check_html.py` 会统计「引用 / 已呈现」并列出缺口。只提不展是原成品
暴露过的真实缺陷：五张表一张没有，式(12)(13)(14)(20) 全部丢失，而它们恰是负循环数、
α/β 互换、残余刚度这些关键证据的载体。

公式用纯 CSS 呈现（`.frac` 分式、`.brd` 大括号、`.op` 正体运算符、变量 `<i>`），
不引 MathJax，保住单文件离线。排版规则：
- 照抄**印刷形式**，包括印刷错误。错误写进「技巧与漏洞」，不在公式块里悄悄改。
- 一个 `.eq` 只放一个编号；推导链拆成多个 `.eq` 依次排列，不要塞进一个分式里。
- 归一化、带帽符号沿用**本文译文已经在用的记法**（如 bS、bN、bE、û），不要临时改用组合变音符
  （U+0303 之类）：组合符与后面的等号会散开成「S~=」，既难看又被误读成新符号。
- 一条 `.eq` 内含两个并列子式（Strength / Stiffness 这类）时用 `<br>` 分行，
  靠 `.body` 居中；不换行会在窄栏里错位折行，把结尾的「1」孤零零甩到第二行。
- 行内变量沿用 `<sub>/<sup>`，与正文一致，不要在行内也用 `.frac`。

表格规则：
- 数值逐格照抄，列不删、行不合并来凑宽度；宽表靠横向滚动。
- `class="flag"` 标批注质疑的值，`class="ok"` 标满足约束的值，让读者一眼看到对照。
- `.src` 行写明页码与原表缺什么（例如「原表未给出修正后预测与试验 N<sub>f</sub> 的比对」）。
- 原表没有的档位不得补进表里；要讨论就在批注中说明，并注明非原表数据。

## 6. 复现档案

读者是「打算把它重跑一遍的人」，不是摘要读者。判据只有一条：**照着这一节能不能把模型搭起来**；
搭不起来的地方必须写清缺什么。

八张卡按固定顺序填，缺哪张 `check_html.py` 就报哪张：

| data-rp | 该卡要回答的问题 |
|---|---|
| geometry | 对象尺寸、铺层顺序、单层厚度、用了哪层对称性 |
| mesh | 单元类型与积分格式、单元数、加密区在哪、收敛没做 |
| material | 体系、取值出处、是否标定过（「未标定」是关键信息，不是可有可无） |
| umat | 实现载体、状态变量清单、退化对象、主公式回链 |
| solve | 载荷形式与 R 比、分析步序列、时间到循环的映射、Jacobian 处理 |
| fail | 判据、退化方式与系数出处、明确不建模的机制及其后果 |
| results | 验证量、对照基准、**具体误差数字**、该对照能否证伪模型 |
| env | 求解器与编译链版本、运行入口 |

三条纪律：
- 每个值都要有出处（页/表/式/图）。**原文没说**分两种：能由上下文推出的，写出推导过程；
  推不出的，进该卡 `.gap` 并同时汇总到 `.rp-gaps`。
- `.rp-algo` 是这一节的核心，不是装饰。按「读入什么 → 判断什么 → 更新什么 → 写回什么」
  逐步写，让人能照着写出子程序骨架。写不出这一步就说明还没读懂。
- 不与正文重复：公式用 `#pNN` 回链，数值指向正文表号。同一张表在两处维护必然漂移。

`results` 卡禁止出现「吻合良好」「效果满意」这类词，只写「预测 405 / 实测 413，偏差 1.9%」这种可核对的句子。

### 配图：按复现角色选，按图核实读数

卡片是整宽单列，不是并排两栏；每张卡可以带缩略图（`.rp-figs`）和指路片（`.rp-links`）。

选图看**复现角色**，不是看手头有什么：

| 卡 | 该放哪张 |
|---|---|
| geometry | 若某张图内插了试件尺寸，那就是几何图（不要另找，也不要声称「论文未给尺寸」） |
| mesh | 网格与加密区那张 |
| umat | 子程序/算法流程图 |
| solve | 加载路径或累积损伤示意图 |
| fail | 一张有代表性的失效指标云图，其余用链接 |
| results | S-N 与应力-应变，加上本地实测图（见下） |

四条硬规矩：

1. **缩略图从正文已内联的 data URI 取，重小编码到 ~620px**。不要从 PDF 重裁，也不要另裁一份：
   两处维护同一张图，迟早不一致。`class="fig rp-fig"` 配 `class="fig-frame"`，点开放大直接复用正文的 lightbox。
2. **读数必须放大到图上看**。低分辨率缩略图会把 6.35 看成 6.38、38.1 看成 304.8。
   带尺寸或数字的图，裁到 500 dpi 以上再读一遍，再写进卡片。
   写「论文未给 X」之前，先把每一张图的内插、坐标轴、色标都看一遍——X 可能就在图里。
3. **本地有算例但没留存结果图时，用它的结果数据自绘一张**，放进 results 卡。
   这是论文给不了的那张图，也是复现档案最该有的证据。图注必须写明「由某某文件绘制，非论文图」。
4. 没放进卡片的图/表/式，用 `.rp-links` 指路；链接的目标 id 必须是正文真实存在的段落，
   写之前先查出图表实际落在哪一段，不要按位置猜。

## 7. 证据纪律

- 数值一律回原文表格核对后再写。表里没有的档位不得称为「论文对照点」。
- 原文有歧义（印刷错误、符号互换、式子端点不自洽）时：译文照抄原文，
  批注里写明「印刷式为 X，按端点约束应为 Y，本文采用 Y 并披露」。不得无声改写。
- **图注说明必须对着裁出来的图写。** 正文对图的描述可能与图的实际形态不符
  （曾出现正文说「曲线」而图实为四联云图）。先看图，再写 figcaption 与 fig-note。
- 图中未标注的量（载荷水平、层号、单位）不得替作者猜。写「原文未标注」即可。
- 批注是阅读分析，不代表原作者观点；footer 的说明行要写明这一点。

## 8. 可核实疑点清单

逐条过一遍，命中就写进批注：

1. 表格出现负值、零值、超出物理范围的数（如负循环数）。
2. 同一参数在正文与表格中取值不一致，或两个参数被互换。
3. 公式在边界条件下不自洽（n=0、n=Nf、应力=0 时结果荒谬）。
4. 结论段引用的表号/图号与正文不符。
5. 精度声明与自身敏感性分析矛盾（「偏差 2%」vs「某自由参数可致 25% 偏移」）。
6. 验证判据被放宽到不可证伪（「落在试验散差内」「均显示明显损伤」而无量化吻合度）。
7. 对照只是并列而非比对（模拟云图与试验照片放在一起，却不比形状/范围/方向）。
8. 机制描述与算法实现不自洽（负反馈说应力下降，但等效循环映射未说明如何迭代收敛）。
9. 模型不含某失效模式，却声称量化该模式有工程价值。
10. 参数数量与标定来源不匹配（四十余个参数仅靠单向试验标定）。

## 9. 总览

`ov-lead`：一句话点破全文骨架的**性质**（是提出新模型，还是复现纠错，还是综述比较），
并说明这个性质如何解释全文详略。

`flow` 五步：问题 → 论点 → 证据 → 反驳 → 结论。每步一个短标题 + 一两句 + 段号 refs。
refs 必须真实存在。

`claim`：一句话版本的核心主张，包含方法、对象、能力边界三要素，不超过 90 字。

`duo`：最强处与最弱处各一条，都要给段号。最强处优先选「可被读者独立复核的证据」；
最弱处优先选「自相矛盾」而非「做得不够多」。
